# 現地確認の手順

高度化PICS には、公開資料だけでは分からない点がいくつかあります。対応交差点で受信した記録は、アプリの改善とテストにとても役立ちます。この文書は、現地で何をどう確かめ、どう共有するかをまとめたものです。

## 安全のために

- 車道や横断歩道の上で立ち止まって操作しないでください。歩道の、ほかの歩行者の妨げにならない場所で操作してください。
- 横断中は画面を見ずに、実際の信号と周囲を確認してください。
- 信号機や制御機の箱に触れたり、近づきすぎたりしないでください。本アプリは受信するだけで、信号機には何も送信しません。

## 確かめたいこと

| # | 項目 | 分かること |
| --- | --- | --- |
| 1 | Service UUID の有無 | 「なし」なら、iOS ではアプリを画面に表示している間しか受信できません（バックグラウンド受信やロック画面表示の可否に関わります）。 |
| 2 | 送信機の数 | 1 つの交差点に送信機がいくつあるか。複数あれば、電波強度で近い角を推定できる可能性があります。 |
| 3 | メッセージ種別ごとの発信間隔 | Type 0（名称）、Type 1（位置）、Type 2（信号）がどのくらいの間隔で届くか。表示の遅れと「更新なし」の判定時間の根拠になります。 |
| 4 | 信号の番号と横断歩道の対応 | 1 番〜6 番がどの横断歩道の歩行者信号か。分かれば方向（「前方」など）を表示できるようになります。 |
| 5 | 「残り目安」の進み方 | 8 段階の目安が実際の残り時間とどう対応するか。 |
| 6 | 受信できる範囲 | 交差点からどのくらい離れると受信できなくなるか、電波強度はどう変わるか。 |

## 準備

- Aoshingo をインストールした iPhone（TestFlight 版、または Xcode でビルドしたもの）。
- 行き先の交差点が対応しているかを、e-Gov データポータルの「[高度化PICS整備交差点_csv](https://data.e-gov.go.jp/data/dataset/npa_20221124_0054/resource/6f7e83e1-be28-4030-961f-3b489c9f6ad8)」で確認します。
- あれば、別の端末に [nRF Connect for Mobile](https://www.nordicsemi.com/Products/Development-tools/nRF-Connect-for-mobile)（Nordic Semiconductor 製の BLE 確認アプリ）を入れておくと、アプリの表示と突き合わせられます。
- 横断歩道の配置をメモするための紙や地図アプリ。

## 手順

### 1. 受信と記録を始める

1. 交差点の角の歩道で「受信開始」を押します。数秒で交差点名と信号が表示されます。
2. 右上の「設定」→「受信データの記録」で「受信データを記録する」をオンにします（受信中だけオンにできます）。
3. 記録は、オフにするか「停止」を押すまで続きます。1 つの交差点で 10〜15 分を目安にしてください。

### 2. 「現地確認」欄を記録する（項目 1〜3）

交差点の画面を下にスクロールすると「現地確認」欄があります。数分受信してから、この欄のスクリーンショットを撮ってください。

- **Service UUID**：「なし」か、表示された値。
- **送信機の数**：受信中に見えた送信機の数。
- **Type ごとの件数・平均間隔・最短間隔**。

「受信データ（開発者向け）」を開くと、メッセージ種別ごとの最新パケット（16 進）と解析結果も確認できます。

### 3. 信号の番号と横断歩道の対応を調べる（項目 4）

1. 交差点の略図を描き、横断歩道ごとに名前を付けます（例：「北側の横断歩道」）。地図アプリで方角を確認しておくと確実です。
2. 1 つの横断歩道の歩行者信号が赤から青に変わる瞬間を見て、同時にアプリで青に変わった番号を確認します。
3. 青点滅や赤に変わる瞬間でも、同じ番号が変わるかを確かめます。
4. すべての横断歩道について繰り返し、次のような表にまとめます。

   | 番号 | 横断歩道 | 確認できた変化 |
   | --- | --- | --- |
   | 1 番 | 北側（東西方向に渡る） | 赤→青、青→青点滅 |
   | 2 番 | … | … |

複数の横断歩道が同時に変わる場合は、変わり方の違う時間帯（右折専用の時間など）を待つと区別しやすくなります。

### 4. 「残り目安」を調べる（項目 5）

対応している交差点では、信号の下に 8 段階の「残り目安」が表示されます。

1. 歩行者信号が青に変わった瞬間から、ストップウォッチで時間を計ります。
2. 「残り目安」の段階が変わるたびに、経過時間をメモします（画面収録を使うと後で確認しやすくなります）。
3. 青点滅と赤に変わった時刻もメモします。

### 5. 受信できる範囲を調べる（項目 6）

交差点から離れる方向に歩き、「交差点の情報」欄の電波強度と、「更新なし」になった地点をメモします。距離は地図アプリで測ってください。

### 6. nRF Connect で突き合わせる（任意）

1. nRF Connect の「Scanner」で、Manufacturer data の Company ID が `0x01CE` の端末を探します。
2. 次の点を確認し、スクリーンショットを撮ります。
   - Advertising interval（広告間隔）
   - Service UUIDs
   - Connectable かどうか
   - Tx Power Level
3. Aoshingo の「現地確認」欄の表示と食い違う点があればメモします。

### 7. 記録を止めて共有する

1. 「受信データを記録する」をオフにするか、画面下の「停止」を押します。
2. 「設定」→「受信データの記録」→「記録ファイル」で、ファイル名をタップして共有します。
3. 右上のメニューの「記録ファイルを再生」で、記録の内容を確認できます。再生中のデータは実測データとして送信されません。

## 記録ファイルの形式

記録ファイル（`aoshingo-YYYYMMDD-HHMMSS.jsonl`。同じ秒に記録を始め直したときは末尾に `-2` などが付きます）は JSON Lines 形式で、受信したパケット 1 件が 1 行になります。

```json
{"emitter":"E1","manufacturerData":"CE010000022A00001234ABCD311384848484","rssi":-67,"t":1794290000.123}
```

| フィールド | 内容 |
| --- | --- |
| `t` | 受信時刻（Unix 秒、ミリ秒精度） |
| `manufacturerData` | iOS が受け取った Manufacturer data（会社 ID `CE01` を含む）の 16 進 |
| `rssi` | 電波強度（dBm） |
| `serviceUUIDs` | 広告に含まれていた Service UUID（あれば） |
| `localName`、`txPower`、`connectable` | 広告に含まれていた値（あれば） |
| `emitter` | その記録の中での送信機の呼び名（E1、E2…） |

記録には緯度・経度も、iPhone ごとの送信機の識別子も含まれません。ただし、受信時刻と交差点 ID（交差点の位置はデータに含まれます）から、**いつその交差点にいたか**は分かります。公開の場に共有するときは、このことを踏まえて判断してください。
