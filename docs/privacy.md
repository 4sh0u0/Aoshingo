## 1. 基本方針

- アカウント登録は不要です。広告、アクセス解析、トラッキング、第三者の SDK は使っていません。
- 受信したデータは、初期状態では端末の外に送信しません。
- 端末の外に送信するのは、利用者が「実測データの提供に協力する」を選んだ場合の、下の「4. 実測データの提供」に書いた情報だけです。
- このほか、試験版（TestFlight）や App Store の仕組みとして、Apple がクラッシュの記録などを集めて開発者に共有することがあります（「10. Apple から受け取る情報」）。

## 2. 端末の中だけで扱う情報

| 情報 | 使い方 |
| --- | --- |
| 受信した Bluetooth 信号（高度化PICS） | 信号の状態を表示するために、メモリ上で扱います。受信のみで、信号機には何も送信しません。 |
| 受信データの記録ファイル | 設定で「受信データを記録する」をオンにしたときだけ作ります。端末内（アプリの書類フォルダ）に保存し、利用者が共有しない限り端末の外に出ません。受信した信号データ（交差点 ID と、信号機が発信する交差点の位置を含む）と受信時刻のほか、電波強度（丸めない値）、Service UUID、送信機の Bluetooth の名前など、受信した電波の情報を記録します。送信機は E1、E2… と表記します。利用者の現在地（緯度・経度）は含みませんが、交差点 ID、交差点の位置、受信した時刻を含むため、いつどの交差点にいたかは分かります。共有するときはご注意ください。 |
| 設定 | 表示の配色、画面を消さない設定、実測データの提供の選択などを端末内に保存します。信号ごとに名前、知らせ方、音、振動を設定した場合は、その内容を交差点 ID ごとに端末内に保存します。どの交差点の信号を設定したか（よく通る交差点など）が分かるため、端末を人に渡すときはご注意ください。設定画面の「信号ごとの設定をすべて消去」で消せます。実測データには含めず、送信しません。 |
| 時刻表と推定の記録 | 実測データの提供に協力している場合だけ、サーバーから受け取った時刻表（すべての交差点の分）を端末のキャッシュに保存し、受け取ってから 7 日まで使います。受信した信号が推定と 5 秒より大きくずれた時間帯は、交差点 ID、信号の番号、日付を端末内に記録して、その日のうちは推定を止めます（翌日以降に消します）。この記録から、その日にどの交差点を通ったかが分かります。どちらも送信せず、提供をやめると削除します。 |

アプリを削除すると、これらはすべて端末から削除されます。

## 3. 位置情報とモーション

- 位置情報の利用許可は、実測データの提供に協力している場合だけ求めます。協力しない場合は求めません。
- 位置情報は、交差点から見たおおまかな方向（8 方位）と距離（6 区分）、現在地の精度（4 区分）、歩く向き（8 方位）と速さ（3 区分）を端末内で求めるため、また「推定」の画面で交差点までの距離を求めるため（交差点から 80 m 未満では推定を出しません）だけに使います。利用者の現在地の緯度・経度は、保存も送信もしません。
- 「モーションとフィットネス」の利用許可も、実測データの提供に協力している場合だけ求めます。iPhone が判定した動きの種類（止まっている・歩いている・走っている・自転車・自動車などの乗り物の 5 区分）を、歩行者と車両を見分けるためだけに使います。加速度などのセンサーの値そのもの、歩数、過去の動きの記録は読みません。
- どちらも許可しなくても、信号の受信と表示はすべて使えます。許可しなかったものは「不明」として送信します。位置情報を許可しない場合、「推定」の画面には推定を出しません。

## 4. 実測データの提供（任意）

初回起動時に協力するかどうかを選べます。どちらを選んでも、使える機能は同じです。設定画面でいつでも変更できます。

### 送信する情報

協力している場合だけ、アプリが実際の信号を受信している間に、次の情報を送信します。デモや記録ファイルの再生中のデータは送信しません。

| 情報 | 内容 |
| --- | --- |
| 交差点 ID | 信号機が発信している 8 桁の ID |
| 受信した信号データ | 信号機が発信しているデータそのもの（交差点名、交差点の位置、信号の状態など）。間引いて送信します。 |
| 信号の変化 | 信号ごとの状態の変化（例：赤 → 青）と「残り目安」の変化、その時刻（0.1 秒単位）、変わる前の状態が続いた時間と周期（0.1 秒単位） |
| 電波強度 | 5 dB 単位に丸めた値 |
| 方向と距離 | 交差点から見た利用者の方向（8 方位）と距離（10 m 未満、10〜20 m、20〜40 m、40〜80 m、80〜160 m、160 m 以上の 6 区分）、現在地の精度（4 区分）、端末の向きと歩く向き（それぞれ 8 方位）、歩く速さ（止まっている・歩いている・それより速いの 3 区分）。方向と距離を合わせると、交差点のまわり数十 m のどのあたりにいたかが分かります。 |
| 動きの種類 | 止まっている・歩いている・走っている・自転車・自動車などの乗り物のどれか（iPhone のモーション判定による区分。判定に自信がないときは「不明」）。歩行者と車両を見分けるために使います。 |
| 周りの Bluetooth 機器の数 | 直前 30 秒に見えた、PICS 以外の Bluetooth 機器の数を、0、1、5、10、20、50、100 以上の区分に丸めたもの（混み具合の目安）。機器の識別子は端末のメモリーにだけ置いて 30 秒で忘れ、送信しません。 |
| 送信機の情報 | Service UUID、送信機の数、送信機ごとの送信出力と接続できるかどうか、受信の件数と間隔、途切れずに受信できた時間帯 |
| 「現地確認」欄の印 | 印を付けたとき（テスター向け）だけ、どの番号の信号がいま向いている横断歩道か、または押しボタンを押したことと、そのときの端末の向き、交差点から見た方向と距離、時刻（秒単位） |
| 送信した時刻 | アプリが送信を始める直前の端末の時刻（ミリ秒単位）。端末の時計が合っているかを確かめるためだけに使います。サーバーは確かめた結果（2 秒以内に合っていたかどうかの区別）だけを残し、この時刻そのものは保存しません。 |
| アプリのバージョン | 例：`aoshingo-ios/0.1.0` |

送信する情報を増やしたときは、前に「協力する」を選んだ人にも、次にアプリを開いたときにもう一度選んでもらいます。選ぶまでは何も送信せず、未送信のデータは削除します。信号の変化の時刻を 0.1 秒単位にし、送信した時刻を加えたため、すでに協力している人にも同意のやり直しをお願いしています。

### 送信しない情報

利用者の現在地（緯度・経度）、機種、OS のバージョン、言語・地域、広告 ID、氏名・メールアドレスなどの個人情報は送信しません。なお、受信した信号データには、信号機が発信する交差点の位置が含まれます。

このほか、App Attest の鍵の ID（keyId）を送ります。協力をオンにしたときに作られる、端末ごとに異なる値です。送るのは鍵の登録と送信用トークンの取得のときだけで、実測データの送信には含めません（「5. 不正なデータを防ぐ仕組み」）。

### 送信のタイミング

受信したデータは、最大 10 分間分ずつ 1 回の送信にまとめます。受信中は、およそ 1 分ごとに、まとまったデータを送信します。アプリを閉じたときや受信を止めたときは、その時点までのデータをまとめて送信します。送信に失敗したときは、間隔を広げながら再試行します。サーバーがその日の受け付けの上限に達しているときは、翌日（UTC）まで待ちます。送信できなかったデータは端末内に最大 50 件まで保存し、6 日を過ぎたものは送信せずに削除します。

送信には、最長 6 時間有効な送信用トークンを付けます。その間の送信には同じトークンを使うため、サーバーは受け取るときに、同じ時間帯の送信どうしを同じ端末からのものと見分けられます。サーバーはトークンを確かめるためだけに使い、実測データと一緒には保存しません。ただし、送信内容の時刻は 0.1 秒単位なので、保存したデータを時刻順に並べると、同じ人が続けて通った交差点を推測できる可能性があります。時刻表を受け取るときも同じトークンを付けます。このときは交差点を指定せず、すべての交差点の時刻表を受け取るため、どの交差点の時刻表を見たかはサーバーに伝わりません。

通信内容と形式の詳細は [送信 API の仕様](field-data-api.md) をご覧ください。

## 5. 不正なデータを防ぐ仕組み（App Attest）

偽造されたデータの混入を防ぐため、Apple の App Attest を使い、送信元が正規の Aoshingo アプリであることを確認します。

- 協力をオンにすると、アプリは端末の安全な領域（Secure Enclave）に鍵を作り、Apple のサーバーで証明を受けます。この処理には [Apple のプライバシーポリシー](https://www.apple.com/legal/privacy/) が適用されます。
- 鍵の ID（keyId）は、協力をオンにしたときに 1 つ作られる値です。鍵の登録と送信用トークンの取得のときだけ、開発者のサーバーに送ります。
- サーバーは鍵の ID、公開鍵、署名の回数、App Attest の環境（開発用か本番か）、登録した日と最後に使われた日（どちらも日単位）を、実測データとは別の表に保存し、実測データとは結び付けません。実測データの行には、鍵の ID も送信用トークンも保存しません。
- サーバーは、最後に使われた日から 30 日を過ぎた鍵の ID と公開鍵を削除します（最後に使われてから最長で 31 日と 18 時間ほど）。
- 送信用トークンには鍵の ID を含めません。協力をオフにすると、アプリはこの鍵を破棄し、もう一度オンにすると新しい鍵を作ります。
- 鍵の ID は端末のキーチェーンに保存するため、協力をオフにしないままアプリを削除すると、端末に残ることがあります。残った鍵の ID は、もう一度インストールして協力をオンにするまで使いません。オンにしたときに、残った鍵が使えなければ新しい鍵を作ります。

## 6. サーバーでの扱い

- サーバーは [Cloudflare Workers](https://workers.cloudflare.com/) と D1 データベースで運用しています。
- 通信を届けるために Cloudflare は IP アドレスを処理しますが、サーバーのプログラムは IP アドレスや国などを示すヘッダーを読まず、記録もしません。アクセスログやトレースの記録は無効にしています。Cloudflare 自身の扱いについては [Cloudflare のプライバシーポリシー](https://www.cloudflare.com/privacypolicy/) をご覧ください。
- 受け取った日時は「日」単位でだけ記録します。送信内容に含まれる信号の変化や受信の時刻（0.1 秒単位）は、そのまま保存します。
- サーバーは、送信された時刻と受け取った時刻の差を調べ、端末の時計が 2 秒以内で合っていたかどうかの区別（合っている・合っていない・調べていない）だけを、実測データの行に残します。送信された時刻と差そのものは保存しません。
- 受け取った実測データは 90 日間保存し、その後は毎日 1 回の処理で交差点ごとの集計（信号ごとの変化の回数を時間帯別に数えたもの、信号や「残り目安」が続いた秒数と周期を曜日・時間帯別に数えたもの、電波強度と方向・距離ごとの受信回数、横断歩道の印の数など）に置き換えてから削除します。受信の間隔、途切れずに受信できた時間帯、押しボタンの印、動きの種類は、集計に残さずに削除します。受け取ってから削除するまでは、通常は最長で 91 日と 18 時間ほどです。ただし、1 日に届いたデータが多くて 1 回の処理で終わらなかったときや、処理が行われなかった日があったときは、残りを翌日以降の処理に回すため、これより長く保存されることがあります。集計には個々の送信を区別できる情報は残りません。集計は期限を定めずに保存します。
- サーバーは、信号ごとの周期と青になる時刻（位相）を求めた時刻表を、毎日 1 回の処理で作ります。時刻表は交差点・信号の番号・日の種類（平日・土曜・日曜）・30 分ごとの時間帯ごとに、周期、位相、青と青点滅の長さ、使った日数と送信の数、最後に使った日を持ちます。作るときは、受け取った日がその前の日までのデータだけを使い、端末の時計が合っていた行だけを使います。
- 時刻表と、信号機が最後に発信した交差点の名前と位置は、期限を定めずに保存します。どちらも個々の利用者の情報を含みません。
- 削除したデータも、Cloudflare D1 の復元機能（Time Travel）により、削除から 7 日間はデータベースごと削除前の状態に戻せる形で残ります。戻せるのはサーバーの運用者だけです。

## 7. 利用目的

- 信号の番号（1 番〜6 番）がどの横断歩道に当たるかを確かめるため（「現地確認」欄の印と、歩く向き・交差点からの方向と距離、歩行者か車両かの区別から推定します）
- 信号機ごとの発信間隔、送信機の数、受信できる範囲を調べるため
- 信号の周期、青の長さ、「残り目安」1 段の長さを時間帯ごとに調べ、残り時間の予測や「残り目安」の表示、信号の判定の正確さを改善するため
- 実測データの提供に協力している利用者のアプリに、信号の周期から推定した「次の青の始まり」のおよその時刻を示すため（時刻表を使います。推定は横断の判断には使えません）

時刻表は、実測データの提供に協力している利用者のアプリにだけ提供し、公開しません。集計結果や時刻表を公開する場合は、事前にこのポリシーを更新してお知らせします。

## 8. 第三者への提供

実測データを販売したり、広告などの目的で第三者に提供したりすることはありません。サーバーの運用（Cloudflare）と不正防止（Apple）のために、上に書いた範囲でこれらの事業者が処理することがあります。法令に基づいて開示を求められた場合は、法令に従って対応します。

## 9. 提供の停止と削除

- 設定画面で実測データの提供をオフにすると、端末内の未送信のデータはすぐに削除され、以後は何も送信しません。
- すでに送信したデータは、利用者や端末と結び付けて保存していないため、個別に探して削除することができません。受け取ってから通常は最長で 91 日と 18 時間ほどで集計に置き換えられ、個々のデータは削除されます（6. に書いたとおり、これより長くなることがあります）。

## 10. Apple から受け取る情報（TestFlight と App Store）

アプリ自体には、アクセス解析やクラッシュの報告を集める仕組みを組み込んでいません。ただし、Apple の配布の仕組みを通じて、次の情報を Apple から受け取ることがあります。

### 試験版（TestFlight）

- TestFlight で試験版を使うと、Apple はクラッシュの記録と利用状況（インストールや起動の回数、クラッシュの回数、機種、OS のバージョン、端末の言語など）を集め、開発者に共有します。TestFlight の仕組みのため、テスターはこれを止められません。
- メールで招待した場合は、招待に使ったメールアドレスと名前も開発者に表示されます。公開リンクから参加した場合は表示されません。
- TestFlight からフィードバックを送ると、コメントとスクリーンショットに加えて、通信事業者、タイムゾーン、通信の種類、電池の残量なども開発者に共有されます。スクリーンショットには交差点名など画面に表示された内容が写るので、送る前にご確認ください。

### App Store 版

- App Store で配布を始めたあとは、利用者が iPhone の「設定」→「プライバシーとセキュリティ」→「解析および改善」で「App デベロッパと共有」をオンにしている場合に、Apple からクラッシュの記録と利用状況の統計を受け取ります。Apple は、個人を特定できない形で共有します。

### 開発者による扱い

- これらの情報は、不具合の修正とアプリの改善、テスターへの連絡のためだけに使い、第三者に提供しません。
- 不具合を GitHub の Issue など公開の場所に書き写すときは、名前、メールアドレス、スクリーンショットなど、人や場所が分かる情報は載せません。
- App Store Connect 上の情報は、Apple が定める期間保存されます。開発者の手元に写したものは、不具合の修正が済んだら削除します。Apple による扱いは「[TestFlight とプライバシー](https://www.apple.com/jp/legal/privacy/data/ja/test-flight/)」と [Apple のプライバシーポリシー](https://www.apple.com/legal/privacy/) をご覧ください。

## 11. このポリシーの変更

内容を変更するときは、公開版のページと GitHub のリポジトリで変更を公開し、重要な変更はリリースノートでもお知らせします。送信する情報を増やす場合は、改めて利用者の同意を得ます。

- サポートページとプライバシーポリシーのページの「メールアドレスを表示」ボタンを押したときだけ、迷惑メールを防ぐために Cloudflare の [Turnstile](https://developers.cloudflare.com/turnstile/) を使います。ボタンを押すと、ブラウザーは Cloudflare（challenges.cloudflare.com）からスクリプトを読み込み、ロボットによる操作でないかを確かめます。このとき Cloudflare は、確かめるために必要な情報（IP アドレス、ブラウザーや端末の情報など）を処理し、確認のために Cloudflare のドメインで Cookie やブラウザーの保存領域を使うことがあります。ボタンを押さなければ、Turnstile は読み込まれません。Cloudflare の扱いについては、[Turnstile のプライバシーに関する補足（英語）](https://www.cloudflare.com/turnstile-privacy-policy/) と [Cloudflare のプライバシーポリシー](https://www.cloudflare.com/privacypolicy/) をご覧ください。
- 確認が済むと、ブラウザーは確認の結果（1 回だけ使える符号）を、開発者が Cloudflare Workers で動かしているプログラムに送ります。プログラムは、その結果が正しいことを Cloudflare に問い合わせてから、メールアドレスを返します。通信を届けるために Cloudflare は IP アドレスを処理しますが、このプログラムは IP アドレスや国などを示すヘッダーを読まず、何も保存せず、アクセスログやトレースの記録も無効にしています。
- ほかに GitHub や Cloudflare のサービスをサイトで使うときは、使い始める前に、サービスの名前、使う目的、そのサービスに送られる情報をこの節に書き加えます。
